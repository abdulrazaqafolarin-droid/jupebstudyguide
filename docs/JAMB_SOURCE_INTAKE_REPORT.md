## Quality and publication rules

- All 4,669 candidates are staged as `needs_review` by the importer; no record is auto-published.
- No correct answer or explanation is generated by the importer. The source pack does not provide a verified answer key/solution set; the Biology file explicitly notes that answers/solutions are excluded.
- The 901 A–E candidates are retained for historical past-question browsing. They are not truncated or relabelled to fit the four-option current CBT selection rule.
- The 419 figure-placeholder candidates require their original figure/image to be attached and reviewed before publication.
- The 378 candidates with no source reference and 37 with multiple references require year/reference resolution before they can be approved.
- Candidate text similarity and content hashes are used to detect duplicates. Duplicates must be resolved before publication.
- Source file SHA-256 is retained and rechecked by the server against the original uploaded file in the private `question-source-documents` bucket.
- A Rutex admin must record the source-use permission/rights note and review each item. A question without a reliable answer key can be approved as ungraded; a scored key/explanation requires independent verification.

## How to stage the source packs

From the repository root:

```bash
python scripts/import_jamb_sources.py
python -m unittest scripts.test_import_jamb_sources
```

The generated JSON appears under `private-question-sources/generated-json/jamb/` (gitignored). In `/admin/jamb-questions`, upload each generated subject JSON with the exact, unchanged matching original `.txt` file, confirm the rights note, stage the batch, then review and publish only valid items.

## Semantic indexing after publication
Publishing a reviewed question triggers the existing shared embedding-job queue. The JAMB admin screen processes up to 50 queued items after publication and exposes an additional bounded indexing action. The worker uses the configured Gemini embedding key. If that key is unavailable or the provider fails, the source questions remain published, lexical retrieval remains available, and failed vector jobs stay queued for retry; no source question is discarded.
